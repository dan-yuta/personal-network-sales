# 01. プロジェクト概要

## プロジェクト名

**人脈営業ツール**（仮称）

## 一行説明

自分の人脈経由（既存知人・紹介・コミュニティ + これから出会う新規）で進める独自営業活動を支えるツールです。Notion上の既存「営業候補リスト」に接触ログDBを足し、UIから「次の一手」が時系列で追える状態にします。

---

## 背景

```
                  営業活動の流れ
  ┌─────────────────────────────────────────────────────────┐
  │  業務提携契約 → 独自営業フェーズ開始 → 営業活動本格化   │
  │                                                          │
  │                ▲                                         │
  │                │                                         │
  │       ここから営業活動が本格化、ツールが必要              │
  └─────────────────────────────────────────────────────────┘
```

- 業務提携先とのパートナーシップ契約を締結
- 独自営業フェーズへ移行
- 対象: **自分の人脈経由（既存知人・紹介・コミュニティ + これから交流会や仕事で会う新規）**。業種縛りなし

営業活動では「誰に・いつ・何を話したか・次に何をするか」を高密度で管理する必要があります。
既存のNotion DB（営業候補リスト）はあるものの、Notionだけでは接触履歴が時系列で追えず、営業作業のテンポも出ません。
そこで、AI-Driven Schoolの月次課題（workspace-ui-kit を自分の業務向けに作り変える）を機に、自分専用の営業UIを構築します。

---

## 目的

| # | 目的 | 達成指標 |
|---|------|----------|
| 1 | 接触ログを時系列で追える状態を作る | 「いつ・どの手段・何を話したか」が候補者単位で1画面で見える |
| 2 | 朝イチで「今日アプローチすべき相手」が見える | ステージタブで未連絡・アプローチ中候補を瞬時に絞り込める |
| 3 | ログ追加のテンポを下げない | 1件記録〜次のログ追加まで体感1秒未満 |
| 4 | 既存Notionワークフローを壊さない | 既存「営業候補リスト」DBはそのまま使い続けられる |

---

## スコープ

### やること（IN）

```
┌───────────┐   ┌───────────────┐   ┌─────────┐   ┌─────────┐   ┌───────┐
│  リード   │ → │ アプローチ中   │ → │ 商談中  │ → │  契約   │   │ ＝対象  │
└───────────┘   └───────────────┘   └─────────┘   └─────────┘   └───────┘
                       │
                       ├── 失注（記録のみ）
                       └── 保留（記録のみ）
```

- 見込み顧客リストの管理（既存「営業候補リスト」DBの閲覧・編集）
- ステージ別での絞り込み（未連絡 / アプローチ中 / 商談中 / 契約 / 失注 / 保留）
- 接触ログの時系列記録（電話・メール・LINE・訪問・オンライン会議・SNS）
- 次回アクション・期限の管理
- 紹介ネットワーク情報（親レコード・間柄）の表示

### やらないこと（OUT）

- 受注後のアフターフォロー、リピート営業、紹介獲得管理
- 契約書・見積書管理
- 入金・請求管理
- チーム共有（複数人での同時利用）
- スマホ最適化UI（出先閲覧はNotionアプリで代替）

---

## 対象顧客像（人脈ベース＋新規開拓）

```
   ┌─────────────┐     ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
   │  既存の     │     │  紹介経由   │     │ コミュニティ│     │ 新規(これから│
   │  つながり   │     │  (バック    │     │  同期・知人 │     │ 交流会・仕事 │
   │  (再連絡)   │     │   人脈)     │     │  経由       │     │ で会う人)    │
   └─────────────┘     └─────────────┘     └─────────────┘     └─────────────┘
          │                   │                   │                   │
          └───────────────────┼───────────────────┼───────────────────┘
                              ▼
                  提携サービスの導入提案
              (業種は問わず、関係性ベース)
```

- **対象**: 自分の人脈経由（既存知人・紹介・コミュニティ + これから交流会や仕事で会う新規）。業種縛りなし
- **接触単位**: 1人=1レコード（個人と所属企業をセットで管理）。1社内に複数担当者がいれば、それぞれ個別レコードで管理
- **規模感**: 同時進行は数十件規模（リスト+詳細型UIが適正）
- **人脈活用の肝**: Notion DB の「間柄（コミュニティ）」「親レコード（紹介元）」「バック人脈（後ろ盾）」を活かした関係性ベースの営業
- **新規開拓の取り込み方**: 交流会・仕事で出会った人は、その場で「間柄」に交流会名を記録、必要に応じて「親レコード」で紹介者を明示。既存の人脈ネットワークに新規ノードとして接続される

## 採用したアプローチ

```
   ┌───────────────────────────────────┐
   │ 道A: 踏襲ルート (workspace-ui-kit) │ ◄── 採用
   └───────────────────────────────────┘
                  │
                  ├── 4ペイン構造を尊重
                  ├── designing-workspace-ui スキルで規律維持
                  ├── 立ち上がり最速 (Day1から動くものがある)
                  └── サンプルの色・角丸トークンに従う

   ┌───────────────────────────────────┐
   │ 道B: 自由ルート (ゼロから)         │ ◄── 不採用
   └───────────────────────────────────┘
       理由: スケジュール的に間に合わず、独自業務思想も
             まだ言語化しきれていないため、踏襲ルートで助走する
```

道Aを採用した理由:
1. 人脈営業の業務構造は「リスト+詳細」型で表現でき、4ペイン構造と相性が良い
2. 営業活動の立ち上げに追従する以上、立ち上がりの速さが最優先
3. AI開発・shadcn/uiの慣熟がまだ浅いため、サンプルの規律に従った方が安定する
4. 道A→道Bへの移行は現実的なため、まず道Aで助走する
