### ペイン責務サマリ

| ペイン | 役割 | データソース | 操作 |
|--------|------|--------------|------|
| **Pane1** | ステージタブで絞り込み | 営業候補リストDB「進捗状況」（7段階） | タブ切り替え |
| **Pane2** | 選択ステージの候補者一覧 | 営業候補リストDB（Notion） | 行クリックで選択・DnDでステージ移動 |

## Pane1: ステージタブ

既存DBは6段階ですが、UI上は「主導線4 + 副導線2」で視線負担を最小化します。

```
┌──────────────────┐
│  メインステージ  │
├──────────────────┤
│ ● 未連絡   (12)  │ ◄── まだ手をつけていない見込み客
│ ○ アプローチ中(8)│ ◄── 接触開始、反応待ち含む
│ ○ 商談中    (3)  │ ◄── アポイント獲得後、提案フェーズ
│ ○ 契約      (1)  │ ◄── 受注完了
├──────────────────┤
│  サブステージ    │
├──────────────────┤
│ ▽ 失注      (5)  │ ◄── 折り畳み or 別枠
│ ▽ 保留      (2)  │
└──────────────────┘
```

### 設計判断の根拠

- **朝イチ動線を最優先**: 「未連絡 → アプローチ中 → 商談中 → 契約」が日々の業務動線
- **失注・保留は隠す**: タッチ頻度が低く、メイン4と同列に並べると朝イチの視線が散る
- **件数バッジ**: 各ステージの未対応件数を即座に把握できるように

### 編集可能な項目（インライン編集）

現状（2026-06-09）、Pane3 のプロフィール系フィールドは**ほぼ全項目がインライン編集可能**で、編集は **Notion 候補者DB に永続化**されます（楽観的更新＋失敗時通知）。

| フィールド | 編集UI | 同期方針 |
|-----------|--------|----------|
| ステージ | ヘッダーのステージバッジ（ドロップダウン） | 楽観的更新＋失敗時ロールバック＋Toast |
| 優先度 | ドロップダウン（営業条件カード） | 楽観的更新＋失敗時通知 |
| 想定取引規模（下限/上限） | テキスト | 楽観的更新＋失敗時通知 |
| 次回アクション日 | 日付ピッカー（Base UI Popover + Calendar） | 楽観的更新＋失敗時通知 |
| 次回の用件 | テキスト | 楽観的更新＋失敗時通知 |
| 名前・フリガナ・生年月日・接触経路・バック人脈・営業担当 | テキスト / 日付 | 楽観的更新＋失敗時通知 |
| 連絡先（Email・電話・住所） | テキスト | 楽観的更新＋失敗時通知 |
| 会社・職務メモ / 営業メモ | テキストエリア | 楽観的更新＋失敗時通知 |
| 評価4軸（関係性の強さ / 興味度合い / レスポンス速度 / 紹介ポテンシャル） | 星クリック（1-5、×でリセット） | 楽観的更新＋失敗時ロールバック＋Toast |

> 永続化の実装メモ:
> - テキスト/テキストエリア欄は uncontrolled（`defaultValue` + onBlur 保存）のため、保存失敗時に画面を自動で巻き戻すことはできず**通知のみ**（リロードで Notion 最新に揃う）。
> - ステージ・評価4軸・アーカイブは state を持つため、失敗時に**ロールバック**まで行う。
> - 全書込は `writeChainRef` のキューで直列化し、連打・順序逆転・Notion レート制限を回避する。
> - 当初は「書き込みは Phase 3 で実装」「デバウンス保存」を想定していたが、本接続フェーズ（Phase D・2026-06-09）で楽観的更新方式に統一して実装済み。

### 編集不可（読み取りのみ / スコープ外）

- 最終連絡日（接触ログから自動算出。Notion 側に denormalized 同期され、Pane2/Pane3 バッジに使用）
- 担当者（Notion person 型）・親レコード／間柄（relation）・名刺（file）・リンクURL・郵便番号（**今回スコープ外として据え置き。読み取りのみ・書き込みなし**）

> 顧客企業名・顧客名（名前）は当初「誤書き換えリスク回避のため読み取り専用」としていたが、現状は名前フィールドもインライン編集可能（Notion へ永続化）に変更している。

### タブB: 連絡文作成（AI下書き生成）

> **現状（2026-06-10）= Anthropic 本接続済み（発展課題 Phase E 完了）**。シーン11種・媒体3種の選択、補足入力、画像添付（最大3枚/5MB・vision）、生成ボタン、微調整ボタン（丁寧/カジュアル/短く）、再生成、コピー、「接触ログとして保存」まで動作する。`draftMessageAction`→`generateDraftMessage` で実 AI 生成（モデル＝Sonnet）。**AI 生成は `ANTHROPIC_API_KEY` のある環境で動作**し、ローカル／公開 Vercel の両方にキーを置いて有効化（キー未設定環境はサンプル文 `getMockDraft`）。コスト防御はアプリ側のレート制限ではなく **Anthropic Console の前払い残高/月額上限（財布側・auto-reload OFF）で管理**し、**Upstash 等のアプリ側レート制限は不採用**。以下は設計仕様。

人脈ベース営業の核心。初回接触から契約締結、契約後の **派生紹介の連鎖** まで、営業フェーズ全体をAIが下書きします。

#### カバーするシーン（11種・営業フェーズ全体 + 派生紹介の連鎖）

| # | フェーズ | シーン | 用途 |
|---|----------|--------|------|
| 1 | アプローチ前 | 初回声かけ（既存知人） | 既存知人への「お久しぶりです」系 |
| 2 | アプローチ前 | 初回声かけ（新規の人） | 交流会・仕事先で出会った直後の「初めまして」系 |
| 3 | アプローチ前 | 紹介依頼 | 共通知人を介して、まだ接点のない新規対象を紹介してもらう |
| 4 | アプローチ中 | フォローアップ | 直近接触の続き「先日の件ですが」系 |
| 5 | 商談中（営業） | 提案・サービス紹介 | サービス内容の初回提案、価値→根拠→次のステップ |
| 6 | 商談中（商談） | 商談・条件すり合わせ | 導入時期・予算感・意思決定の流れ等の論点整理 |
| 7 | 商談中（クロージング） | クロージング・意思確認 | ご導入の方向性確認、判断材料の補完、次のアクション提示 |
| 8 | 契約 | 契約締結・条件確定 | 契約書送付、開始日・支払条件・担当窓口の最終確認 |
| 9 | 共通 | お礼 | 紹介・面会・契約への感謝 |
| 10 | 契約後・派生 | 派生紹介の依頼 | 契約・お礼の流れから、**既存知人を起点に別の方を紹介してもらう**。関係性ができている前提で、紹介者への感謝を起点に新たな繋がりを広げる |
| 11 | 共通 | 再アプローチ | 失注・保留からの再接触 |

> **「営業・商談・クロージング・契約」観点 + 派生紹介の連鎖**: 単発の連絡文ではなく、営業ステージの遷移（未連絡→アプローチ中→商談中→契約）に沿って AI のプロンプトが切り替わる設計。さらに **契約後に「派生紹介」を回す**ことで、人脈ベース営業の真価である「紹介の連鎖」が回り続ける。各フェーズで「何を強調すべきか」（例: クロージングでは判断材料の確認、契約では条件の整理、派生紹介では紹介者への感謝と相手の負担配慮）が AI 側の SYSTEM_PROMPT に組み込まれている。
>
> **③紹介依頼 と ⑩派生紹介の依頼 の違い**:
> - ③ は **新規対象の開拓** — 接点のない相手を、共通知人経由で繋いでもらう（候補者リストに新ノードを追加するイメージ）

#### 設計判断のポイント

- **AIに渡す情報を絞る**: 候補者基本 + 接触ログ直近3件 + 紹介ネットワークまで。Notion側のログ全件はトークン肥大化・コスト増・個人情報送信量増のためカットする
- **過去のやり取りは「任意・どちらでも可」**: メールはテキストコピーが早い、LINEはスクリーンショットの方が早い。両方サポートし、ユーザーが場面ごとに選べる
- **スクリーンショットは Claude Vision 経由**: Claude Sonnet 4.6 の vision 機能で画像内容を文脈として読み取らせる。トークン消費は画像1枚 ~1500、複数枚は注意
- **画像は最大3枚まで推奨**: LINEの会話履歴は3枚あれば文脈が十分。それ以上はトークンコストに対するリターンが下がる
- **微調整ボタン**: 営業文は一発で決まらないため「もっと丁寧/カジュアル/短く」のクイック調整を標準装備
- **接触ログとして保存**: 「いつ何を送ったか」を後の生成精度向上に活かす（自分の文体傾向の蓄積）
- **送信は手動**: ツール内から直接 LINE/メール送信はしない（クリップボードコピーが最も安全で柔軟）
