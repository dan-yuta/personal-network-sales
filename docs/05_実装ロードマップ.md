## Phase 3: ペイン書き換え

サンプルの採用管理 → 人脈営業ツールへ、4ペインを順番に書き換えます。

### 書き換え順序の依存関係

```
                  ┌──────────────┐
                  │ lib/notion/  │ ← Step 0: 共通基盤
                  │ schema.ts    │
                  │ candidates.ts│
                  │ contact-logs │
                  └──────┬───────┘
                         │
        ┌────────────────┼────────────────┐
        ▼                ▼                ▼
  ┌──────────┐    ┌──────────┐    ┌──────────┐
  │ Pane2:   │    │ Pane1:   │    │ Pane3:   │
  │ 候補者   │ ←─ │ ステージ │    │ 候補者   │
  │ リスト   │    │ タブ      │    │ ダッシュ │
  └────┬─────┘    └──────────┘    │ ボード   │
       │                          └─────┬────┘
       │ (Pane2 の選択が                 │
       │  Pane3/4 の入力)                │
       ▼                                 ▼
  ┌──────────────────────────────────────────┐
  │ Pane4: 接触ログ + 次アクション           │
  │   (Pane3 で選んだ候補者のログを表示)      │
  └──────────────────────────────────────────┘
```

### 推奨順序

1. **Step 0 (基盤)**: `lib/notion/` の schema・candidates・contact-logs を整備
2. **Step 1 (Pane2)**: 候補者リストの取得・表示（ハードコードなしで Notion から）
3. **Step 2 (Pane1)**: ステージタブで Pane2 を絞り込み
4. **Step 3 (Pane3)**: 選択候補者の詳細表示
5. **Step 4 (Pane4)**: 接触ログの表示（読み取りだけ先に）
6. **Step 5 (Pane4)**: 接触ログの追加・編集（Phase 4へ繋ぐ）

### designing-workspace-ui スキルの活用

書き換え依頼時の AI への指示例:

> 「Pane2 の候補者リストを Notion の営業候補リスト DB から取得して表示するように変えてください。`designing-workspace-ui` スキルを使って、4ペインの規律に沿って書いてください」

## リスクと対策

| リスク | 対策 |
|--------|------|
| Notion API レート制限に引っかかる | 1回の画面遷移で並列リクエスト数を3以下に抑える |
| Notion 側のスキーマ変更で UI が壊れる | zod スキーマで実行時バリデーション、エラーは画面上に表示 |
| 2台 PC 間で `.env.local` が反映されない | `.env.local` は `.gitignore` 対象なので各 PC で個別に作成する (本番秘密の重複管理リスクを避ける標準運用) |
| 楽観更新で「保存できていなかった」事故 | 失敗トースト + エラーログを `localStorage` に残す |
| スケジュールに間に合わない | Phase 3 までで一旦使い始め、Phase 4-5は走りながら追加する |

## Phase 番号の体系（docs/05 と docs/06 の対応）

このファイル（docs/05）は **実装の流れに沿った Phase 1〜5**、`docs/06_やることリスト.md` は **個別タスクの管理単位として Phase 0〜6** で番号を振っており、表記が異なります。対応関係は以下の通り:

| docs/05 (実装ロードマップ) | docs/06 (やることリスト) | 内容 |
|--------------------------|------------------------|------|
| — | Phase 0: 前提準備 | クローン・robocopy・npm install |
| — | Phase 1: 設計（グループセッション準備） | grill-me・docs整備・課題図解・Surgeデプロイ ← 2026-05-13 時点で完了 |
| Phase 1: Notion 側準備 | Phase 2: 外部サービスのセットアップ | Notion Integration 作成・接触ログ DB 作成 |
| Phase 2: 接続疎通 | Phase 3: ツール実装 (一部) | .env.local 設定・@notionhq/client インストール・lib/notion/client.ts |
| Phase 3: ペイン書き換え | Phase 3: ツール実装 (Pane 書き換え部分) | Pane2/3/4 を実 Notion データに切替・連絡文 API 接続 |
| Phase 4: 楽観更新・同期 | Phase 3: ツール実装 (楽観更新部分) | useOptimistic ヘルパー・Server Action・エラートースト |
| Phase 5: 仕上げ・運用開始 | Phase 4: 仕上げ・運用開始 | 期限切れ強調・紹介ネットワーク表示・名刺サムネ |
| — | Phase 5: 提出（月次課題提出時） | スクリーンショット撮影・受講生ポータルへアップロード |
| — | Phase 6: 将来拡張 | 紹介ネットワークグラフ・受注後フォロー・スマホ最適化 |
