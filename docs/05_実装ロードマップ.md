| Notion API レート制限に引っかかる | 1回の画面遷移で並列リクエスト数を3以下に抑える |
| Notion 側のスキーマ変更で UI が壊れる | zod スキーマで実行時バリデーション、エラーは画面上に表示 |
| 2台 PC 間で `.env.local` が反映されない | `.env.local` は `.gitignore` 対象なので各 PC で個別に作成する (本番秘密の重複管理リスクを避ける標準運用) |
| 楽観的更新で「保存できていなかった」事故 | 失敗トースト + 書込直列化（実装済み）。失敗時は楽観追加を自動取消・スナップショットへロールバック |
| スケジュールに間に合わない | Phase 3 までで一旦使い始め、Phase 4-5は走りながら追加する |

### 実際に起きた想定外（2026-06-09 実績）

| 事象 | 真因と対策 |
|--------|------|
| Vercel デプロイが連続失敗（`ENOENT .next/routes-manifest-deterministic.json`、`onBuildComplete` 段階。ローカルビルドは毎回成功） | 真因は `next.config.ts` の `outputFileTracingRoot: projectRoot`。サブディレクトリ（`tool`）に固定していたため Vercel のデプロイアダプタ（Next 16.2 で安定化した Adapters API）のマニフェスト探索パスがずれていた。**`outputFileTracingRoot` を削除して解決**（修正コミット `2950b8b`）。アダプタはローカルで走らないため再現せず、ローカル成功・Vercelのみ失敗の症状と一致 |
| Notion スキーマが docs の想定とズレていた | 実装前に実 Notion スキーマを fetch して検証（進捗状況が実は7段階＝紹介進行中あり、フリガナ/生年月日/想定取引規模の列は実在しなかった）→ ローカルを7段階に修正＋デモDBに不足列を追加 |
