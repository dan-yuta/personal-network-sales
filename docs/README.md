## 更新方針

- 設計を変更するときは、対応するドキュメントを**同じコミットで**更新する（コードと設計のドリフト防止）
- 「決まった事」と「未決事項」を明確に分けて書く
- アスキーアートで視覚化する（Mermaid は使わない方針）
- 文体はビジネス資料用（敬称「さん」統一・カジュアル表現なし）
