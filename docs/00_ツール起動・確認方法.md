# 00. ツール起動・確認方法

人脈営業ツール（`tool/` 配下の Next.js プロジェクト）をローカルで起動して動作確認するための手順書。
**このファイルだけ読めば、初めて触る人でも起動できる状態**を目指しています。

> **公開 URL**: https://personal-network-sales.vercel.app （デモ DB・ダミーデータ・無認証）。
> ローカルで起動せず動作を見たいだけならこちらを開けば確認できます。以下はローカル起動の手順です。

---

## 0. 前提条件

| 項目 | 要件 | 確認コマンド |
|------|------|------------|
| Node.js | v18 以上（推奨: v24.x） | `node --version` |
| npm | v10 以上 | `npm --version` |
| Git | 任意のバージョン | `git --version` |
| OS | Windows 11 / macOS / Linux | - |

Node.js が未インストールの場合は https://nodejs.org/ から LTS 版をダウンロードしてください。

## 2. 依存パッケージのインストール

`tool/` 配下に Next.js プロジェクトの依存が定義されているため、`tool/` で `npm install` を実行します。

```powershell
cd tool
npm install
```

**所要時間**: 2〜3分（771 パッケージ）

成功時の出力例:

```
added 771 packages, and audited 772 packages in 2m
```

---

## 2-5. 環境変数の設定（Notion 接続）

Notion は接続済みです。候補者データ・接触ログは Notion のデータソースから読み書きします。
起動するには `tool/.env.local` に以下を設定します。`tool/.env.example` がテンプレートです。

```powershell
copy .env.example .env.local   # tool/ 配下で実行（macOS / Linux は cp）
```

`.env.local` に最低限必要なのは次の 3 つです。

| 環境変数 | 役割 |
|---------|------|
| `NOTION_TOKEN` | Notion Internal Integration Token（v5 は `ntn_` で始まる） |
| `NOTION_DB_CANDIDATES` | 営業候補リスト DB の「データソース ID」 |
| `NOTION_DB_CONTACT_LOGS` | 接触ログ DB の「データソース ID」 |

> DB は 2 セット運用です（公開 Vercel = デモ DB／ローカル = 本番 DB を env で切替）。
> 値の取得方法は `.env.example` のコメントを参照してください。

### 環境変数を設定しない場合（フォールバック）

`NOTION_TOKEN` が未設定の場合に限り、`tool/data/candidates.json` のシードデータで起動します。
接続前でもアプリを立ち上げてスクリーンショットを撮るなどの用途には使えますが、
**編集内容は Notion に書き込まれず永続化されません**（リロードで元に戻ります）。

> 連絡文作成（AI）機能（発展課題＝Phase E）は**実装済み**です。`ANTHROPIC_API_KEY` を
> `.env.local` に設定すると実 AI で生成、未設定ならサンプル文を表示するため、**起動自体に
> このキーは必須ではありません**（AI を実際に動かしたいときだけ設定）。

## 3. 開発サーバーの起動


## 4. ブラウザでアクセス

```
http://localhost:3001   (PORT=3001 で起動した場合)
http://localhost:3000   (デフォルトの場合)
```

> WSL などが同居する環境では `localhost` が IPv6 (`::1`) に解決されて画面が開けないことがあります。
> その場合は `http://127.0.0.1:3000`（または起動ポート）でアクセスしてください。

## 7. トラブルシューティング

### Q1. `npm install` で警告 / 失敗する

```
npm warn deprecated whatwg-encoding@3.1.1: ...
2 moderate severity vulnerabilities
```

→ これらは依存パッケージ側の警告で、動作には影響なし。無視して OK。

### Q2. `npm run dev` でポートエラー

```
Error: listen EADDRINUSE: address already in use :::3001
```

→ 既に別プロセスがポート3001を使っている。以下のいずれかで対処:

```powershell
# 別ポート(3002)で起動
$env:PORT=3002; npm run dev

# またはポート3001 を使っているプロセスを kill
Get-NetTCPConnection -LocalPort 3001 | Select-Object -ExpandProperty OwningProcess | ForEach-Object { Stop-Process -Id $_ -Force }
```

### Q3. ブラウザで画面が真っ白 / エラー画面

1. dev サーバーの **ターミナル出力** にエラーが出ていないか確認
2. ブラウザの **DevTools コンソール** (F12) でエラーを確認
3. `npm run dev` を Ctrl+C で停止 → 再起動

### Q4. 「人脈営業ワークスペース」ではなく「採用管理ワークスペース」と表示される

→ **`tool/` ではなく `100_tool/workspace-ui-kit/`（テンプレート原本）を起動している可能性**。

`tool/` (実装モジュール) で起動しているか確認:
```powershell
cd "C:\Users\dangi\src\personal-network-sales\tool"
pwd
```

### Q5. 候補者リストが空 / エラー

考えられる原因は 2 つです。

**(a) Notion 接続時**: `.env.local` の `NOTION_TOKEN` / `NOTION_DB_CANDIDATES` が誤っている、または
対象 DB に Integration が接続されていない可能性。Notion 側で対象 DB を開き、⋯ → コネクト で
当該 Integration が接続済みか確認してください。dev サーバーのターミナルに Notion API のエラーが
出ていないかも確認します。

**(b) フォールバック時**（`NOTION_TOKEN` 未設定）: `tool/data/candidates.json` が空または壊れている可能性。
```powershell
git -C "C:\Users\dangi\src\personal-network-sales" status
git -C "C:\Users\dangi\src\personal-network-sales" diff tool/data/candidates.json
```
で差分を確認 → 必要なら `git restore tool/data/candidates.json` で復元。
