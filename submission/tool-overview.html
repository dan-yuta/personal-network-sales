A. 解決したい課題

grill-meスキルで詰めた「ツールでどんな課題を解決したいか」

現状の困りごと

  • Notion の営業候補リストは接触履歴が時系列で追えない（進捗詳細テキスト1個だけ）
  • 朝イチで「今日アプローチすべき相手」を絞り込むのに、Notionのビューを切り替える手間
  • 「久しぶりに連絡したい人」「商談後のフォロー」に毎回ゼロから文章を考える時間
  • 接触を記録しようとしても、Notion 側に「履歴を積み上げる」仕組みが無く、進捗詳細テキストに上書きするしかない

ありたい姿

  • 接触ログが時系列で見える（いつ・どの手段・何を話したか）
  • ステージタブで3秒で「今日の対象」が見つかる
  • AIに紹介ネットワークと接触履歴を渡して連絡文を下書きさせ、コピーして送る
  • 記録するたびに新しい行として履歴が積み上がる（接触ログDBで時系列管理）

C. 連絡文作成タブ

既存つながりへの久しぶり連絡も、新規の人への初接触も。AIが「次の一手」を下書き（Pane4 の「連絡文作成」タブ）

カバーするシーン（5種）

  • 1.初回声かけ（既存知人への再連絡 + 新規の人への初接触）
  • 2.フォローアップ（接触ログを踏まえた次の一手）
  • 3.紹介依頼（共通知人を介して架け橋）
  • 4.お礼（紹介・面会・契約への感謝）
  • 5.再アプローチ（失注・保留からの再接触）

対応媒体（3種）

  • メール: 件名+本文・敬語・段落構成
  • LINE: 短文・親密トーン
  • 電話用トーク台本: 話し言葉・要点リスト

D. 工夫したポイント

設計・実装でこだわった全10点のうち、特に伝えたい6点を抜粋。残り4点と詳細は同梱の docs/07_工夫したポイント.md を参照。

① grill-me で1問ずつ詰めた

計画段階で発生する全ての分岐を AI に1問ずつ質問してもらい、合意できた決定だけを設計に書き残した。「なぜその判断にしたか」が docs に残り、後から判断ログを辿れる。

② 既存 Notion DB を尊重

既存の「営業候補リスト」をそのまま流用し、ゼロからスキーマを作らない判断。データ移行コストゼロ。既存の Notion ワークフロー（検索・フィルタ）も壊さない。

③ Pane4 をタブ化

元の workspace-ui-kit テンプレートでは Pane4 が「ステージ詳細編集」専用だったところを、タブ切替で「接触ログ / 連絡文作成」を同居できる構造に。横スクロールや別画面遷移なし。

④ 連絡文に Vision 対応

過去のやり取りを「文面コピペ」と「スクショ画像添付」の両方で AI に渡せる設計。メールはコピペ、LINEはスクショ、と場面で使い分け可能。

⑤ テンプレ参照と実装の分離

workspace-ui-kit 原本は 100_tool/ フォルダに「書き換え禁止」で保管し、編集は別フォルダ tool/ にコピーして実施。テンプレートのどこを変えたかが Git の差分機能で明示できる。

⑥ モック先行

Notion / Anthropic API のセットアップ前から、接触ログ・連絡文タブを「サンプルデータで動く状態」に。グルセでもデモは API 接続なしで完結。後で本物 API に切り替え。

ここに載せていない残り4点：接触ログDBだけ追加 / Pane1ステージタブ転用 / テンプレ語彙の置換（採用用途→営業用途） / 設計と実装の同期コミット
全10点の詳細は docs/07_工夫したポイント.md および notes/2026-05-12_craftsmanship.md を参照
